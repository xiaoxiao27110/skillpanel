# 任何时刻恰有一个激活场景,手动开关实时写回

系统不存在「无场景」状态:首次启动自动创建默认场景接管当时状态,删除激活场景自动切换,删光即重生全开的默认场景。激活场景下的每一次手动开关立即改写该场景的关名单,而不是标脏等待显式保存、也不是下次切换即被冲掉的临时态。

理由:用户的心智模型是「我在哪个场景,就在编辑哪个场景」,手动微调本来就该成为场景的一部分;「无激活场景」会给每次手动开关逼出第二套语义。

**Considered Options**:标脏(指示器显示「已修改」+ 显式存回)——需要在控制器里同时维护激活场景与基线 diff 两份状态;临时态(手动改动不追踪,下次切换被冲掉)——会把用户刚做的微调静默丢弃。

**Consequences**:切场景是一次硬收敛,场景名单之外的改动不会残留;误删激活场景会立即 apply 另一个场景,用户会看到 skill 成片变化——删除激活场景前界面必须明确提示。
